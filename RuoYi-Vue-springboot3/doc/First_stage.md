可以，建议你**第一阶段先做人 员信息与资质管理**，这是后面人脸打卡、点到、责任追溯的基础。

建议按这 5 个模块落地：

1. **人员基础档案**  
    姓名、手机号、身份证号、所属单位、角色、岗位、状态、入场/退场状态。
    
2. **人脸信息采集**  
    上传人脸照片，生成/保存人脸特征值，后续给摄像机识别打卡使用。
    
3. **资质证件管理**  
    身份证、安全员证、电工证、监理证、保险、特种作业证等，支持上传、有效期、审核状态。
    
4. **资料审核流程**  
    待提交 → 待审核 → 已通过 / 已驳回 → 已失效。
    
5. **状态维护与追溯**  
    人员启用/禁用、注销、证件到期提醒、操作日志、打卡记录关联。
    

在若依里可以这样做：

- 复用：用户、角色、部门、岗位、文件上传、操作日志、数据字典、代码生成器。

- 第一版先不接 AI，只做人脸照片上传和资料审核。
    
- 第二版再接 InsightFace/YOLO 做人脸特征提取和识别比对。

# 三、你要改造若依的哪些东西

这里最关键。

---

# 1. sys_user 不等于施工人员

很多人会踩坑。

不要：

```text
一个施工人员 = 一个登录账号
```

这是错的。

因为：

很多施工人员：

- 不登录系统
    
- 只做人脸识别
    
- 只公众号打卡
    

所以：

# sys_user 是系统账号

# tb_worker 是业务人员

两者分离。

---

# 2. role 不要复用系统角色

不要：

```text
sys_role
```

来管理：

- 安全员
    
- 监理
    
- 项目经理
    

因为：

sys_role 是：

# 后台权限角色

而：

施工角色是：

# 业务角色

所以：

应该：

```text
worker_role_type
```

用字典管理。

---

# 3. 文件上传统一

所有：

- 人脸照片
    
- 身份证
    
- 安全员证
    
- 保险单
    

统一走：

```text
/common/upload
```
