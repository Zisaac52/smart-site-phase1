# 数据库变更记录（updates）

> **规矩：任何改动数据库的操作**（建表、改表、加菜单 / 权限 / 字典、初始化数据），都在本目录新建一个 SQL 文件，**和对应的代码一起 commit**。这样同伴 `git pull` 后执行新文件，两人的库就能保持一致。

## 为什么需要它

git 只同步**代码文件**，**不同步数据库里的内容**。你用若依代码生成器刷出来的「建表 DDL」和「菜单 SQL」只进了你自己的库——同伴拉到代码却没有这些表和菜单，结果就是**登录后台看不到新菜单、点进去报错**。把这些 SQL 放到这里提交，就解决了。

> 注意：这和「数据库连接账号」是两回事。账号（用户名/密码）**不进仓库**，各自留在本地（项目用 `git update-index --skip-worktree` 忽略了 `application-druid.yml` 的本地改动）。本目录只管「库里有什么表/菜单/数据」。

## 命名规范

`YYYYMMDD_HHMM_简短描述.sql`，例如：

- `20260601_1430_worksheet_module.sql` （作业单模块：建表 + 菜单）
- `20260603_0900_add_camera_table.sql`

> 日期+时间前缀用来保证**执行顺序**；描述建议用英文/拼音，跨 Windows / Linux 不会有文件名编码问题。

## 每个文件写什么

照 `_template.sql` 的结构来：① 建表 DDL ② 菜单 SQL（`sys_menu`）③ 字典（按需）④ 其它初始化数据。

## 同伴怎么用（每次 pull 后）

1. `git pull`
2. 按**文件名顺序**，执行 `updates/` 里**自己还没跑过的**新文件：
   ```bash
   mysql -u <你的本地账号> -p ry-vue < sql/updates/20260601_1430_worksheet_module.sql
   ```
3. 重启后端，新表 / 新菜单就生效了。

> 建议各自记一下「自己跑到哪个文件了」，按顺序补齐新文件即可。
